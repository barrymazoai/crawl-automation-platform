# Amazon Brand 店铺与商品目录入口：独立前置建档设计

日期：2026-09-23。业务路径沿用用户已确认的约定；本文给出实现前的具体设计，尚未实现、部署或执行。这里的“Brand 网站”指 Amazon 上的品牌店铺及商品目录入口，品牌官网仅作为身份核对线索。

## 目标与边界

从数据库中已有 Amazon 商品找出所属品牌，通过商品页的真实品牌入口进入店铺，找到店铺的“全部商品”或可用于后续目录枚举的入口，持久保存品牌与入口的对应关系。以后 Brand 扫描直接使用这些入口；新品牌或失效入口再单独发起建档。

这是独立的准备流程。它不启动商品完整提取、不调用 OCR / Text / Vision、不修改商品上下架状态，也不把找到一个店铺入口算成已完成品牌全量扫描。正在美国主 Mini 上执行的单商品补跑继续按原队列运行。

后续 Brand 主流程另行实现：完整枚举目录并比较历史；新商品走完整单商品流程，已知商品更新价格、销量、rating 等动态数据。是否下架必须有同范围目录完整性证据；本次准备任务不作该判断。

## 输入和身份

采用 [旧库与美国库查漏结果](../quality/2026-09-23-local-product-brand-reconciliation.md)，输入是 [修正后的 1,352 条候选](../quality/evidence/2026-09-23-amazon-brands-corrected.csv)，以及对应的 [完整 JSON](../quality/evidence/2026-09-23-amazon-brand-count-corrected.json)。

- 1,352 是有合法 Amazon 商品链接的旧公司分组；涉及 32,181 个去重 Listing。它不是已确认的 1,352 个独立品牌或店铺。
- 此前 Brand 清单未包含的 192 组全部纳入候选；它们关联的 328 个 Listing 已在美国库中，无需再迁移商品。
- 保留原 `companyId`、来源库、原始名称、已有 V3 `brandId` 候选、全部关联 ASIN 和代表商品 URL。公司 ID、V3 Brand ID、Amazon 店铺身份是三个概念。
- 不按同一个官网域名或名称相似度合并母公司与子品牌，不截断脏名称来强行满足现有 Brand 的 80 字限制。
- 每个候选确定一个代表 ASIN：优先有已验证 HTML 和明确品牌链接的商品，其次使用候选清单中的合法种子。记录选择依据。首轮每个候选只执行一次；失败后不换 ASIN 自动再试。

## 路径选择

| 路径 | 代价与限制 | 本次决定 |
|---|---|---|
| 已有证据提取候选链接，再在新 Mini 验证实际入口 | 可减少重复商品抓取；历史链接只能作为线索，仍需验证当前页面身份 | 推荐；以此作为默认路径 |
| 每个候选重新抓商品页，再进入店铺 | 来源清楚，但已有证据时会重复用额度；仍受共享 24 小时准入限制 | 仅在缺少可用证据且允许新观测时使用 |
| 用品牌名称搜索并猜测店铺 | 名称、经销商、母子品牌容易混淆 | 不自动采纳；可供人工 Review 参考 |

已有 capture projection 中的 `brandRaw` / `storeUrl` 可用于定位原始证据；它们不能替代原始 HTML，也不能独自证明当前入口有效。

## 设备与模块

以 [设备清单](../operations/machines.md) 为连接信息入口。

1. **美国主 Mini：准备任务协调与持久化。** 从已有数据库和 R2 元数据生成候选、记录任务领取与结果、执行共享付费抓取准入、写入品牌入口。使用独立的前置任务队列，不向正在跑的商品队列插入这些任务。
2. **Brand 专用新 Mini：浏览器验证。** 在 `server2@100.84.91.3` 执行有限的商品 → 店铺 → 目录导航，保存证据并返回结构化结果。它不另建生产产品库、不请求 Windows OCR。
3. **入口发布：配置写入。** 校验身份、证据、revision 和幂等键后，将可用目录入口写入现有 `brand_source`，同时持久化更完整的导航与来源记录。写入入口本身不触发抓取。

设计采用现有 Temporal 连接方式：美国主 Mini 上的专用协调 Worker 使用 `amazon-brand-entry-control`，承接 Workflow、主库及共享准入 Activity；新 Mini 的浏览器 Worker 使用 `amazon-brand-entry-browser`。Workflow 按角色明确路由 Activity，避免不同能力的 Worker 竞争同一任务队列。新 Mini 不直接暴露或连接数据库端口。实际新增 Worker 的部署和最小权限连接在实施时验收，不假定已有 90 个 Worker 已包含这些能力。

## 单个候选的流程

1. 以候选 ID 和此次 preparation ID 领取唯一任务，持久化尝试记录。重复提交同一个 ID 只返回既有状态，不能新开一次抓取。
2. 查询现有商品原始 HTML、捕获时间和哈希。先校验证据，再提取商品页的品牌名称与品牌链接。过期历史 HTML 只提供导航线索，不能冒充今日商品观测。
3. 若缺少可用商品证据，由美国主 Mini 的共享准入申请新商品 HTML；同站点同 ASIN 的滚动 24 小时规则与单商品队列共用。命中已验证存档则复用原捕获时间；正在抓取则让出浏览器／网络许可并等待已有结果，不重复收费。失败或发布状态未知时终止本候选，不发第二次请求。
4. 在新 Mini 打开从证据中得到的品牌链接，核验最终域名、品牌标识及店铺身份。没有真实品牌链接，或品牌入口只到泛搜索／卖家页时，记录明确原因进入 Review，不能补造一个 Store URL。
5. 跟随页面真实导航找到 Shop All / All Products 等商品目录入口，保存点击路径、原始及最终 URL。没有统一“全部商品”页时，可以保存多个明确属于该店铺的分类目录，标记 `category_set` 和覆盖范围未知；只有店铺首页、推荐商品或泛搜索结果不能冒充完整目录。
6. 存档本次获取的原始 HTML及必要的页面证据，校验写入回执。关闭本任务全部页面并核验目标消失，记录资源收尾结果。
7. 原子保存已验证映射及来源证据。只有身份、目录范围描述、存档和清理均通过，才发布为后续 Brand 扫描可选入口；否则保留 Review / failure 与已取得证据。

首轮建议浏览器并发为 1，每个候选最多 8 次顶层导航、180 秒业务执行窗口。这是待小批验证的上限，不是已测吞吐。到达上限后停止业务操作并进入清理，不通过增加时长或自动重跑绕过限制。亚马逊访问受阻或需要人工登录／验证时也按上述方式收尾。

8 次导航只限制本任务主动打开或点击的新页面，不把页面内图片等子请求算成 8 次。清理阶段另有最多 30 秒的有界核验；若仍不能证明任务页面和执行已结束，将该浏览器执行位标记为不可接新任务并记录 cleanup pending，交由准确目标恢复处理，不能仅释放账面许可后复用。

## 原始证据与抓取时效

- 商品付费 HTML 抓取必须走已有的跨任务、跨机器滚动 24 小时准入，不在新 Mini 写第二套独立 scraper。成功复用不刷新 capture 时间；失败的同一操作不因时间过去而自动再试。
- 新抓到的商品、店铺、目录 HTML 均保留原始响应字节、URL、capture 时间、站点、SHA-256、字节数及 R2 引用；解析下载内容前先完成存档及读回核验。浏览器执行应具备原始响应留存能力，缺少该能力时不得把 DOM 序列化称为原始 HTML。
- 动态导航可另外保存渲染后的 DOM 与截图，注明 `rendered` 及观察时间；它们是补充证据，不能覆盖原始响应。
- `sourceCapturedAt` 与 `verifiedAt` 分开保存：前者描述种子证据，后者描述这次店铺验证。旧 HTML 可以引导访问当前店铺，但不能据此刷新旧商品指标。
- 入口映射不会每天到期后自动重跑。每次独立建档保留自己的版本和时间，后续扫描发现入口失效时记录原因，再单独安排修复；不静默重置成功映射。
- R2 按引用读取、按需缓存；不预先搬运 32,181 个商品的图片或历史工作目录。

## 持久化与输出

准备任务及结果写入美国主库，CSV / JSON 作为可复核导出，不作为唯一运行状态。新增前置模块的 schema 在实施中走现有数据库 migration；不把运行状态塞进 `brand.note`。

| 字段组 | 必须保存的内容 |
|---|---|
| 身份 | preparation ID、candidate ID、原 company ID 与来源库、原名称、已匹配 V3 Brand ID、名称和身份判断依据 |
| 种子 | Amazon 站点、代表 ASIN、商品 URL、原始 HTML 引用与 capture 时间、提取出的品牌原文和链接 |
| 店铺 | 原始品牌链接、最终 Store URL、可识别的 Store ID、当前页面品牌名、跳转路径 |
| 目录 | 一个或多个目录 URL、入口类型 `all_products` / `category_set`、对应导航路径、范围说明；`catalogEnumerationComplete=false` |
| 证据 | 每页原始 HTML 引用与哈希、必要的 rendered DOM / 截图、verifiedAt、来源版本 |
| 执行 | 状态、错误码及原因、开始／结束时间、任务页 target IDs、清理结果、资源释放结果、结果 revision |
| 发布 | 对应 brand_source IDs、采用的 Brand revision、幂等键与发布回执 |

候选与 Brand 保留显式关联，允许多个旧公司候选经证据验证指向同一个 V3 Brand；一个候选对应多个子品牌时进入身份 Review，不强制一对一。缺少 V3 Brand 的候选，只有得到明确的品牌名称和唯一身份后才建立新 Brand；与现有名称冲突或无法唯一对应时保留 Review。

`brand_source` 继续负责“哪个 Brand 的哪个渠道入口”。新增来源默认 `enabled=false`，目录验证成功不自动启动业务。已有正确来源按 Brand、region 和规范化 URL 幂等复用，不切换其 enabled 状态；不覆盖已有配置或把某个 source 改属另一 Brand。Shop All 与多个分类入口的组合关系保存在前置映射中，后续目录扫描需整体读取该组入口。

发布与完成状态在同一数据库事务内提交。响应丢失时按 preparation ID 只读核对回执；状态仍无法确认则停止并记录结果未知，不重做浏览器或付费抓取。证据只可追加引用，保留历史映射，不在本任务中删除旧证据、旧 Review 或既有 Brand。

## 错误、取消与恢复

任务状态区分 `pending`、`running`、`verified`、`review`、`failed`、`cancelled`；只有发布完成且清理通过才为 `verified`。暂存了部分 URL 不等于成功。

- 品牌身份冲突、没有可信店铺、没有可用目录、达到探索上限：Review，说明已发现及缺少的证据。
- 网络超时、抓取错误、存档失败、异常退出：终止当前业务尝试，保留错误和证据，不自动重试。其余独立候选可在执行位健康时继续。
- 取消：停止准确任务所属的浏览器／provider 执行，完成清理记录；不关闭整个浏览器，不影响用户页面。
- Worker 重启：重新加载 pending 候选；已开始但结果未知的尝试只做状态核对与准确目标清理，不重新执行原业务步骤。
- 成功、Review、失败和取消都必须有清理结果。清理不等于业务重试，清理无法核验时要隔离受影响执行位，不能让失效任务长期占用正常运行许可。

统计必须满足：1,352 = pending + running + verified + review + failed + cancelled。另报已发布 V3 品牌数、店铺数、目录数，它们可以与 1,352 不同。已发现 Store URL 数不能当作 verified 数。

## 验收与推进顺序

1. 补齐新 Mini 的主机身份、SSH、浏览器、权限和资源核验记录；在目标机 Git clone 已确认提交，手动部署独立前置模块。
2. 在 Mini 运行离线契约、状态与存档用例：重复候选幂等、公司／Brand 身份不混淆、多个分类入口、原始与 rendered 证据区分、无 storeUrl、旧证据时间保持、24 小时准入跨任务共享、超时不重试，以及所有终态和异常重启的页面／许可清理。
3. 首次选择 5 个真实候选小批，覆盖已知店铺、192 组新增候选中的普通品牌、公司名与品牌名不一致、历史名称异常、可能没有统一 Shop All 的情形。具体 ASIN 从清单和证据中挑选，保留选择记录，不猜造测试 URL。
4. 逐项核对导航路径、品牌身份、R2 原件、来源配置、清理记录与没有商品队列副作用。样本不具备预期情况时如实记录，不把不存在的异常分支写成通过。
5. 小批验收通过后，使用同一个持久化队列处理剩余 pending 候选；不为每批重写临时脚本，不重排 Review / failed。并发是否提高依据新机实际资源和网站响应再评估。

验收产物为逐候选明细、可用入口导出、Review / failure 原因汇总、R2 证据及清理记录。Brand 完整目录枚举、上新／下线和动态数据刷新另设验收，不能用这 5 个入口验证代替。

## 设计记录与自检

- 项目上下文：已复核旧库查漏、此前 Brand 业务约定、现有 brand / brand_source 契约及单商品恢复记录。
- 交互范围：本次是流程与数据契约，不需要视觉伴随页面。新 Mini 用户名已由用户确认是 `server2`。
- 方案比较：已有证据导航、全部重抓、名称搜索三种路径已比较；保留用户要求的商品 → Brand → 目录路径。
- 业务边界：用户已确认独立前置流程；本文的队列名、导航预算和首批大小是具体设计建议，不记为已上线或已测结果。
- 文档自检：候选数与来源一致；公司／品牌／店铺概念分开；没有把入口验证当成全量目录证明；错误不重试与资源收尾同时约束；原美国单商品任务不受建档启动影响。
- 交付：本轮完成设备记录及设计文档，供用户复核；代码实现、机器接入和实测尚未开始。
