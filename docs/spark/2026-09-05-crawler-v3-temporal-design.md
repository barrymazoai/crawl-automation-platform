# 爬虫 V3：Temporal 编排与独立原子模块设计

日期：2026-09-05 · 版本：V3 / Temporal · 讨论收口评审稿

本文件记录本轮讨论收敛后的设计，供用户复核；不代表已安装 Temporal、实现模块或切换生产。[分阶段计划](../../CRAWLER_V3_PLAN.md) · [HTML 架构图](../crawler-v3-architecture.html)

## 1. 真源、范围与决策

V3 是独立的新系统，不在旧执行链上改造：新入口、配置、模块契约、编排与测试环境分开建设，不接着旧 Job、租约或 Codex 会话执行。旧代码、Claude Code 历史会话和旧任务提供故障样本、业务背景与外部接口线索，不作为正确性标准。

旧解析器、API 客户端、R2 工具和纯函数可以成为复用候选，但必须逐项检查隐藏依赖、自动重试、清理与副作用，并通过新契约测试；记录保留 / 改写 / 不复用的结论和证据。不能因历史任务成功过就判定可靠，也不能把旧批处理、Job 生命周期、成功删文件等行为带进来。开发期间不改旧系统运行方式。

本设计替代 V2 并行化计划中批处理、恢复、清理和调度的约定。产品服务文档仅作外部契约参考，生产准入前须针对实际服务版本验证。

首版范围：Amazon、GNC、Swanson、DTC；单文件处理；产品级推进；独立下线查询；汇总 Dashboard。Target / Walmart 是未来扩展示例，不新增对应适配器。

已比较自研队列加协调层、轻量工作流框架和 Temporal。本轮采用 Temporal 作为执行底座，收益是复用执行看板、调度、恢复、历史与测试工具；代价是 SDK / 确定性约束与服务运维。不在旧队列上再叠一层引擎。

## 2. 不变原则

1. **模块不是机器。** 每个原子角色独立配置、启动、停止、测试、部署；同机多 Worker，同模块多实例。
2. **Temporal 是执行真源。** 管依赖、任务队列、计时、执行历史；不再维护自研 claim / renew / retry_wait 状态机。
3. **编排与执行分开。** Workflow 只做确定性编排；API、Codex、OCR、浏览器、文件与数据库 I/O 放入 Activity。业务核心函数不依赖 Temporal。
4. **OCR 一次一个文件。** 用文件引用、产品 / 变体观察标识关联，不传批次。
5. **可靠交接后释放。** 业务 Worker 完成本步骤即可接下一项，不等下游；正在等待 OCR 服务响应的 Activity 仍属执行中。
6. **产品独立推进。** 好产品独立入库；需要 family 上下文时只限制该 family，不能扩大为全品牌屏障。
7. **失败被动留存。** 不自动重跑业务，Review 保存分类、完整候选和证据，不自动消费。
8. **产物长期保留。** R2 原始、派生、模型输出和完成凭证不随成功任务删除，无 cleanup 阶段。
9. **首版不自动下架。** 下线查询仅记录存在 / 确认缺席 / 未知，不推断全局停产。
10. **复用执行看板。** Temporal UI 看执行详情；自有 Dashboard 看业务汇总、只读 Review 与可选节点健康。
11. **数据完整性门槛只有 Formula + Ingredients。** 两者须有本产品的真实证据；价格、评分、库存等不是入库必填项。公司归属确认和写入安全仍是独立约束。
12. **资源控制按需启用。** 每模块配置并发；仅实际共享的资源需要共同限额，不假设所有 Codex / OCR 实例共用账号，也不默认建设独立资源服务。

## 3. 职责与所有权

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 入口 API | 校验、业务请求 ID、提交 Workflow、入口回执 | 任务领取和依赖调度 |
| Temporal Service | 执行历史、队列、超时、流程状态 | 运行业务代码、启动机器、保存大文件 |
| 编排 Worker | 目录 / 产品 / 下线查询 Workflow | 直接操作浏览器、Clash、模型或数据库 |
| 原子模块 Worker | 拉取指定队列、完成一个职责、返回结果引用 | 决定下游流程、依赖其他模块的文件目录 |
| V3 业务库 | 身份、产物索引、不可变结果、Review、写入凭证、汇总 | 第二套竞争性的执行状态机 |
| R2 + Artifact Resolver | 保存证据、校验并解析本地 / 远端副本 | 成功后自动删文件 |
| 并发配置与共享资源控制（按需启用） | 每模块容量、实际共享的主机 / 账号 / 浏览器 / 出口限制 | 必建的跨机资源服务、业务待办队列或依赖调度 |
| 主机运行层 | 安装、启动、进程监督、部署、健康与凭证注入 | 产品业务依赖 |
| 产品服务 | 按验证过的契约写观测、身份归并与回读 | 爬虫调度 |

业务库可以记录执行 ID 和只读投影，但不复制引擎状态机。资源许可只表示资源所有权，不是另一套业务 Job 租约。入口提交 / 结果登记使用窄范围幂等交接记录，不扩张为自研工作流引擎。

## 4. 多机部署

Worker 主动长轮询 Temporal、领取任务并上报；不需要 Temporal 远程登录机器，也不需要 Worker 暴露公网接单端口。运行环境必须能访问 Temporal、R2 和所用服务。

| 位置（目标拓扑，非已部署） | 独立角色 |
| --- | --- |
| 常驻服务环境 | Temporal Service（托管 / 自建二选一）、入口 API、编排 Worker、业务库、Dashboard；共享资源协调仅按实际需要部署 |
| Mac mini | Amazon、GNC、Swanson、页面、文件、PDF、OCR、Codex 文本 / 视觉、校验等按需启动 |
| 美国 Windows | DTC 浏览器 Worker、隔离浏览器会话、对应 Codex 驱动；默认不管理浏览器网络，继承主机环境 |
| 未来服务器 | 独立承接 PDF、OCR、文本或其他抓取能力，不修改产品业务流程 |

每个实例记录 `hostId / workerInstanceId / moduleId / buildVersion / capabilities`。队列按能力命名，必要时加地区 / 运行时，不默认绑定物理主机。例：`v3.ocr.file`、`v3.pdf.file`、`v3.capture.gnc.browser`、`v3.capture.gnc.scraperapi`、`v3.capture.dtc.browser.us`。同队列消费者须具备一致处理能力。

Temporal 的 Worker Versioning 管执行路由兼容，不替我们安装代码。系统服务 / 容器工具管进程监督；启动检查覆盖 schema、凭证、浏览器 / PDF 引擎、磁盘和网络。不健康实例停止接新任务，保留证据。机器数、Worker 数、账号总并发分别配置。

具体 Temporal / SDK 版本与 Windows 浏览器联动需要实机锁定，不能用“支持分布式”代替兼容性验证。浏览器桌面会话是否可在服务模式运行也是准入检查项。

### 启动、停止与升级

- 启动：读取并校验部署配置 → 组装该角色依赖 → 检查能力、契约版本和所需资源 → 开始接单。配置不合法不得先接单后失败。
- 正常停止：先停止接单，在配置的宽限时间内完成当前操作及可靠交接；再关闭本角色拥有的会话、连接与任务作用域。不关闭其他 Worker 的浏览器，也不删除业务证据。
- 突然退出 / 宽限期耗尽：记录能保存的执行事实；外部请求是否结束未知时按第 9 节核验，不把进程重启等同于允许重跑业务。取消信号不能证明远端副作用已取消。
- 升级：保留在途操作实际使用的版本与配置快照。只将任务路由给兼容实现；不兼容消费者不接该任务，不能用新 schema 猜着处理旧载荷。部署错误先停接单并告警，不批量制造产品 Review。
- Workflow 记录业务策略版本；Activity 输入约束可接受的契约 / 实现版本，完成凭证记录实际构建及模型配置版本。生命周期与回放兼容均要验证，不只验证编译通过。

## 5. 代码组织与设计模式

采用端口与适配器（Ports & Adapters），按功能组织、函数优先、组合与显式依赖注入。TypeScript strict 为主要代码约束；PDF 可用独立 Python 实现。连接、客户端等有生命周期的对象可以用类，不设计大继承树、插件市场或兼容所有引擎的抽象层。

建议目录（只作设计，未创建运行代码）：

```text
contracts/                 # 身份、ArtifactRef、结果、错误、策略版本
modules/
  catalog-discover/        # 与产品处理分开的目录发现
  capture-amazon/          # 各渠道独立部署
  capture-gnc/
  capture-swanson/
  capture-dtc/
  page-extract/
  artifact-fetch/
  pdf-process/
  ocr-file/
  text-interpret/
  image-interpret/
  product-normalize/
  product-validate/
  owner-resolve/
  product-ingest/
  product-verify/
  presence-check/
adapters/
  network/                # static-proxy、clash、scraperapi
  model/                  # OCR / Codex 驱动
  storage/                # R2、本地缓存
  pdf/                    # PDFium
  product-service/        # 写入与回读契约
workflows/                # Temporal 确定性编排
runners/                  # 薄 Activity / 独立 Worker 入口
bootstrap/                # 配置校验、工厂、依赖注册与释放
apps/                     # 入口、业务 Dashboard；共享资源协调按需
deploy/                   # 平台启动配置，不进入业务核心
```

`module.run(input, ports)` 可以单测；runner 注入适配器、日志、取消和限额。角色共享运行库，但不把所有模块装进一个大 Worker。DTC 的 Codex 浏览器驱动属于抓取会话内部的适配器，不等于抓取 Worker 同时承担后续 OCR / 标准化。

### 设计模式的使用边界

| 模式 | 在本系统中负责 | 不做什么 |
| --- | --- | --- |
| Adapter | OCR、模型、存储、网络、产品服务的外部接口转换 | 不把 ScraperAPI HTML 与交互浏览器伪装成等价能力 |
| Strategy | 确实变化的访问 / 证据复用 / 轮动规则 | 不把每条简单校验都做成策略类，不暗中兜底重跑 |
| Dependency Injection | 从外部给业务函数提供窄能力接口 | 不是远程调用，不代替 Temporal，也不把容器传遍业务 |
| 简单 Factory | 根据已校验配置创建具体 Adapter / Client | 不执行抓取、自动切节点或提交业务写入 |
| Repository | Review、结果、身份、产物索引等窄数据访问 | 不读写 Temporal 内部表，不封装第二套 Job 引擎 |

环境变量只提供部署配置。启动时一次性读取、校验并形成配置快照，工厂据此选择实现，再注入模块；不是在每个业务函数内读取全局环境变量，也不在并行任务之间修改环境来切策略。运行配置中的凭证使用秘密引用，实际值仅在 Worker 内解析，不能写进任务载荷、配置指纹明文或日志。

### DI 库候选：Awilix，验证后才锁定

Awilix 支持函数 / 类注册、作用域和注册释放器，不要求特殊注解；作为当前函数优先风格的首选候选，尚未安装或锁定版本。TSyringe、InversifyJS 是已比较的备选，本轮不并装多套容器。[Awilix 官方文档](https://github.com/jeffijoe/awilix)

本项目限定：每个 Worker 进程一个根容器，只在 bootstrap / Activity 运行外壳使用；显式注册，启用严格模式并测试实际依赖图，不自动扫描目录。业务模块使用独立定义的 ports 和普通参数，不调用 `container.resolve`，Workflow 不导入容器。

可安全并发复用的客户端按进程共享；产品数据、页签及请求上下文按操作或显式隔离的浏览器 Lane 管理。任务作用域不是持久 ProductWorkflow 的内存容器，进程内 singleton 也不是跨机器单例。为资源显式注册释放逻辑并在退出时调用；容器不会自动关闭未接入释放逻辑的资源。最小 Worker 要验证构建兼容、任务隔离、依赖解析和退出释放后，才决定最终引入。

### 编码与测试约束

- 外部输入先运行时校验；不使用 `any` 或类型断言掩盖不完整数据。结果使用可区分的类型，不让空对象同时表示等待、失败与成功。
- 模块通常包含入口函数、输入 / 输出 schema、ports、错误和测试；依复杂度拆文件，不机械规定文件数量、行数或每个辅助函数一个包。
- 业务数据不可变地传递与追加保存；不共享一个可被多 Worker 改写的全局产品对象。
- 不隐藏重试、模型修复、Provider 切换、数据库写入或清理。普通单测用 fake Adapter，不请求付费服务或生产库。
- 格式化、静态检查、类型检查、契约与单元测试作为检查门；英文标识符，必要中文解释业务边界。测试覆盖正常、缺失、冲突、外部失败及本模块特有的交接故障。

### 统一模块契约与执行身份

| 项目 | 统一含义 |
| --- | --- |
| `requestId` | 一次业务提交的稳定标识；提交回执丢失时复用，不新建一次采集 |
| `observationId` | 一个来源挂牌 / 变体的一次采集观察；尚未入库也能存在 |
| `operationId` | 该观察中某模块的一次具体操作；重复投递仍用原标识，执行尝试另记 |
| 输入 | 上述关联标识、契约版本、输入指纹、来源 / 文件 / 上游结果引用、所需策略与能力 |
| 输出 | 明确的操作结果、产物 / 来源引用、实际实现与配置版本；成功处理不等于正式入库成功 |
| 错误 | 阶段、分类、稳定错误码、已执行 / 未执行 / 结果未知的事实、证据引用和 `blockedBy` |

业务函数输出交给运行外壳完成持久化、结果登记及完成凭证；不要每个 OCR / 解析函数各实现一遍交接协议。客户端、密钥、本机绝对路径不是跨模块传输契约。

**重复投递与重新采集分开：** 同 operation + 同指纹先核验已完成结果，完整则只交接；在途或结果未知则核验，不再次发起外部调用；同标识不同指纹报冲突，不覆盖。相同操作的并发重复到达必须由幂等操作登记阻止重复提交，登记仅记录执行 / 交接事实，不承担任务领取、重排或依赖调度。

以后明确重新采集同 URL / 产品，要有新 request / observation / operation，不能以 URL 命中旧结果就冒充本次采集。新观察只有在已取得本次来源证据、输入内容 hash 与处理配置 / schema / 实现版本一致时，才可按显式规则复用可缓存的文件处理结果，并记录 `reusedFrom` 与本次产品关联；不会自动复用旧抓取或重放写入。指纹不纳入签名 URL、主机或临时目录等不改变处理含义的字段。

## 6. 原子模块目录

| 模块 | 一次输入 → 输出 | 边界 |
| --- | --- | --- |
| 目录发现 | 品牌 / 站点范围 → 发现项、CatalogManifest | 不等产品处理；完整性不由入库数推断 |
| 产品抓取 | 一个挂牌 / 变体观察 → 页面、字段、文件来源 | 浏览器导航 / 切规格 / 读取在一个隔离会话内，不拆给不同 Worker |
| 页面整理 | 一份页面 → 原文 / 表格 | 不做最终营养范围排除 |
| 文件获取 | 一个来源文件 → 已校验 ArtifactRef | 校验真实媒体类型、hash，不按扩展名猜 |
| PDF | 一个 PDF + 操作 → 文字或逐页图片引用 | 不内部串接 OCR / Codex；页图保留父文件与页码 |
| OCR | 一张图片 → 原始文字与来源 | 不判断业务、不入库、不处理批次 |
| Codex 文本 | 明确范围文本证据 → 带来源候选 | OCR 文本路径依赖 OCR，页面路径可以并行 |
| Codex 视觉 | 一张图 + 意图 → 视觉候选 | 按证据计划启用，不默认每张图双跑 |
| 标准化 | 单 SKU 候选 + 按需封闭 family 上下文 → 规范候选 | 不全品牌打包，不自造产品服务身份键 |
| 确定性校验 | 候选 + 证据 → Formula / Ingredients 完整或具体问题 | 不要求价格等可选字段，不暗中调用模型修复 |
| 公司归属 | 来源身份与候选 → 唯一可信公司 / 未匹配 / 歧义 / 冲突 | 不猜归属、不自动建公司；失败完整保留候选 |
| 写入 | 一个合格 SKU 观测 → 回执 / 未知 | 首版全局串行，不等品牌完成 |
| 回读 | 写入标识与预期 → 核验结果 | 只读，不在失败时再次写入 |
| 下线查询 | 一个 Listing / URL → exists / confirmed_absent / unknown | 不直接下架，不推断全局停产 |

目录可分页发布已可靠发现的项，但传输分页不是 OCR 执行批次。发现项有稳定 ID 防重复启动；最终目录 manifest 单独封闭。Sales Channel 与 DTC 都持续发布，不等全部品牌、全站或一份最终大 JSON。发现 URL 即可安排详情抓取；已验证文件可安排 OCR；不意味着只有 URL 就能入库。

## 7. 流程与并发规则

### 三类流程

- `CatalogWorkflow`：发现 → 可靠发布产品请求 → 封闭目录 → 完整同范围目录才生成缺席核查。目录后来失败不撤销已发布产品证据。
- `ProductWorkflow`：一次挂牌 / 变体观察；组织抓取、文件、OCR / 文本 / 视觉、标准化、校验、归属、写入与回读。
- `PresenceWorkflow`：独立下线查询，可由目录比较触发或单独提交。

目录关闭不得取消已启动产品：对子流程显式配置关闭策略，或通过可靠启动凭证启动独立产品 Workflow。长目录采用分页、子流程或 Continue-As-New 的边界在压力验证中锁定；不建立保存所有文件正文的无限品牌流程。

### 首版证据规则（本次文档评审范围）

1. 启动时固定 `evidencePlanVersion` 和选择路径，所有证据绑定同一 `observationId`。
2. 页面整理 → Codex 文本路径，可与文件获取 → 按需 PDF → OCR / 文本处理路径并行；各路径内部遵守前后依赖。PDF 文字直接进入文本路径，页图则逐文件 OCR。
3. OCR 文本解析必须等对应 OCR；未返回不能视为空文本。
4. 视觉直读由计划指定。成功但证据不足可走已声明补充路径；OCR 请求失败不自动换 Provider 或改跑视觉。
5. 最终判断等待用于确认 Formula、Ingredients 和产品归属的必需证据到明确终态；必需结果未返回不等于缺失。可选字段 / 可选证据的缺失或调用失败只记录自身问题，不在两项核心数据已确认且无相关冲突时阻塞入库；不能通过证据计划偷偷增加价格、评分等必填项。
6. 并行结果追加保存，按版本和来源汇合，禁止最后写覆盖先前结论。
7. 需要 family 比较时只使用本次已封闭的 family manifest；所需上下文无法建立则隔离该产品 / family，不无限挂起全品牌。
8. 每 SKU 独立验收 / 入库；family 共享上下文，不要求全体成功。

证据屏障是 Workflow 等待，不是占槽的 Join Worker；标准化、冲突判断、校验则是独立模块。

### 并发配置与共享资源控制（按需启用）

基本单位是实际资源池，不是电脑数量。每个模块先配置自身并发；同机 CPU / 内存、同一浏览器 Lane、同一外部账号 / 配额池或可变出口确有共享时，再配置共同约束。不同主机使用独立账号和独立资源可以独立运行；移动机器但仍使用同一账号不能凭空增加配额。当前账号与资源共享关系须通过部署清单确认，不预设 Codex 文本、视觉和 DTC 一定共用预算。

不要求先建独立中央资源服务。单实例用本地容量；同机跨进程共享时使用能约束所有相关进程的协调方式；确有跨机共享时再接共享许可后端。实现选取最小必要范围，不把每个进程的并发 1 误当共享总并发 1。资源适配通过配置替换，业务模块无需重写。Temporal Worker 容量、队列每秒速率和外部账号同时执行数不是同一个限制。

启用共享许可时：

- 业务 Activity 前短操作申请；无许可立即返回，Workflow 持久等待通知 / 有界频率复查，不占昂贵执行槽。只存容量、许可、世代、占用者，不建第二份业务待办。
- 获许可再安排操作，开始外部请求前校验；许可失效且尚未执行回到资源等待，不记业务失败。预留窗口有界，排队超出窗口先释放，不长期占住资源等 Worker。
- 有界预取，不在 Worker 内先领几十个任务排本地 semaphore。失去所有权的实例不得发起新调用；运行中副作用未知先核验 / 隔离，不仅凭租期到期转交。

所有模式均保留磁盘、R2、积压和网络健康背压；持续流水不等于容量无限，普通排队不直接进入 Review。全局写入保护是第 11 节的独立数据安全约束，不随可选资源协调的关闭而取消。

## 8. 文件、R2 与本地复用

`ArtifactRef` 包含 `artifactId / observationId / 来源产品与变体标识 / kind / mediaType / sha256 / byteSize / R2 key / 产生模块与版本`。PDF 页另带 `parentArtifactId / pageIndex`；文件与多个产品的关系显式记录。

OCR 输入为 `{ file: ArtifactRef, operationId, inputFingerprint, schemaVersion }`。来源 URL 可记录，临时签名 URL 不是永久 ID。尚未入库时使用来源身份与内部 observation ID，不要求先有正式 productId。

读取顺序：当前运行环境可访问的本地副本 → 校验 hash / 大小 / 完整性 → 直接使用；否则从 R2 稳定 key 获取授权读取地址、下载并校验。同一物理机器但容器路径不可见仍走 R2。没有有效副本就报告 artifact 错误，不猜路径或使用旧文件。

同机复用省重复下载，不省持久备份。R2 至少保有可靠上传的原件、派生结果和完成清单。Temporal 载荷仅放引用和摘要，不放图片 / PDF / 大段日志。

不配置成功后的 cleanup。生产准入检查 R2 lifecycle 是否会过期删除。首版不自动清除唯一的本地完成证据；将来缓存回收必须另定政策，先确认 R2 副本与引用完整。

## 9. 处理完成与可靠交接

以下是结果 / 交接事实，不是复制 Temporal 执行状态机：

| 事实 | 含义 | 能否推进下游 |
| --- | --- | --- |
| `computed_local` | 处理已返回，本地结果与完整清单原子保存 | 否 |
| `artifact_durable` | 结果与清单已在 R2，校验通过 | 还需登记 |
| `result_registered` | 业务库已登记结果、指纹和产物关系 | 等引擎确认 |
| Temporal 已记录 Activity 完成 | 引擎持有可消费引用 | 按依赖推进 |
| `delivery_unknown` | 登记 / 回执状态未知 | 只核验，不重做业务 |

完成清单含 operation ID、输入 hash、代码 / 模型配置 / schema / 策略版本、所有输出 hash、完整标记、外部请求 ID（如提供）。只有原图、文件存在、`.ready` 文件名或部分日志不算完成证明。

正常路径：处理一次 → 完整结果 → R2 → 幂等登记 → Activity 返回引用 → 引擎记录完成。交接阶段可以占用短执行时间，不等于陪下游等待。

异常路径：先核验清单与登记。输入 / 版本一致且输出完整，只补传 / 补登记 / 报完成。不能伪造已超时 Activity 成功；超时后的流程通过独立只读核验 Activity 采用已验证结果。只剩本地结果时由交接恢复功能上传，不再 OCR。机器不可达、半份结果或身份冲突进入 Review。

允许连接恢复、幂等投递重发、只读核验；不允许因此重跑抓取 / OCR / Codex / 数据库写入。交接重试有界、可观察，超限保留事实和 Review，不能无限占槽。

## 10. 错误、Review 与历史任务

业务 Activity 显式 `maximumAttempts: 1`。检查内部 OCR / HTTP / Codex / 产品客户端的自动重试、模型修复循环和 Provider 切换。Workflow Task 重放、连接恢复与业务重跑区分。ScraperAPI 等提供商可能内部重试，我们只能约束不重复提交，不能保证其源站请求次数。

未执行且资源不可用 → 等待；已执行失败 / 未知 → 核验证据，无法确认则 Review。下游用 `blockedBy` 关联根因，不伪装成也执行失败。产品级捕获异常，避免取消兄弟产品。

Review 保存在业务库，含原始错误、分类、阶段、host / worker / Workflow / Activity ID、输入输出引用、完整候选与 Facts、完成凭证、确认根因。Review 登记本身失败时保留引擎历史与告警，不能计为已经可靠落库。

| 分类 | 示例 |
| --- | --- |
| SOURCE | CAPTCHA、目录不完整、页面不可读 |
| RUNTIME | CDP、页签冲突、schema 缺失、启动失败 |
| ARTIFACT | 缺文件、类型错误、hash 不符、R2 传输 |
| PROCESSING | OCR / Codex 调用失败、输出契约错误 |
| VALIDATION | 必需证据缺失、配方 / 规格冲突 |
| IDENTITY | 来源身份或公司 / 品牌归属不确定 |
| INGEST | 写入失败 / 未知、回读不一致 |
| SCHEDULER | 重复实例、取消不生效、生命周期异常 |
| UNCLASSIFIED | 证据不足，原因无法确认 |

Review 不挂等待人工的长期 Workflow，不自动消费，不设“重试全部”。以后明确要求重试，建立关联新请求，复用经验证且输入未变的上游，保留原 Review。Temporal UI Reset / 重新启动不是日常恢复按钮，须限制权限并遵守业务规则。

历史成功任务：证据建立隔离验证副本，运行新实现；旧输出仅参考，以人工确认样例 / 确定性规则验收。历史失败任务：保留原 Review、补分类；复现必须另建显式测试副本，不自动进入生产重跑。

## 11. 入库与下线查询

### 产品入库条件

数据完整性条件只有 **Formula 和 Ingredients 均已抓出**。两者必须来自本次产品 / 变体的真实证据，不是非空占位符、其他规格的标签或模型编造内容；已知核心字段冲突仍要保留 Review，不能用最后到达的结果覆盖。缺 Formula 记 `VALIDATION.FORMULA_MISSING`，缺 Ingredients 记 `VALIDATION.INGREDIENTS_MISSING`，都缺则记录两项。价格、评分、库存、营销文案等缺失不阻止入库，不扩成一套额外必填字段清单。

公司归属是另一个已确认的安全边界：可信 companyId 或唯一可信别名匹配可继续；未匹配、多个候选或冲突分别记录 `IDENTITY.COMPANY_UNMATCHED / COMPANY_AMBIGUOUS / COMPANY_CONFLICT`，该产品进被动 Review。不自动新建公司或猜关联。候选、Formula、Ingredients、OCR / 模型输出、图片和匹配理由完整留存，其他产品照常推进。

满足上述条件即可进入写入队列，不保证外部写入已经成功。若实际产品服务还要求其他字段，P0 应报告契约不兼容并在生产准入前解决，不能编造字段或擅自增加业务入库门槛。

### 写入保护

每个就绪 SKU 独立进入写入队列。首版一个激活写入部署、并发 1，并用共享全局写入许可阻止第二实例；不能把每台并发 1 当全局串行。

写入许可有占用者和世代。产品服务不支持 fencing 时保守交接：旧写者是否停止 / 旧请求是否结束无法确认，不自动转交许可；只读核验仍可执行，其他抓取处理不停止。

写入和回读独立。稳定幂等身份与请求指纹固定；回执丢失记录 `write_unknown`，先回读，不认为“没有写入”。产品库写权限仅由写入适配器持有。

首版外部提交始终使用 `partial` 安全语义，禁止触发缺席下架的 full 收口。独立产品提交 run 或已验证可增量追加的共享 run，由 P0 针对实际服务确认；未验证不得生产写入。内部 observation ID 与外部提交 run ID 分离。

### 独立下线查询

完整、同渠道同品牌 / 站点的目录发现集合，与历史 Listing 做差。不是用成功入库集合做差；抓到但 OCR 失败的产品仍算发现。目录不完整不自动推断缺席；单链接请求可独立提交。

只输出 `exists / confirmed_absent / unknown`、时间和证据。验证码 / 网络失败 / 缺货都不是已下架。首版不写 inactive，不推断跨渠道全局停产。

## 12. PDF 与网络

### PDF

推荐 PDFium / pypdfium2 独立 Python 模块，移除 Swift / AppKit / PDFKit 绑定。PDFium 非线程安全，并发用隔离进程；限制页数、尺寸、内存和时间，坏文件、加密文件、超大文件分类报告。跨平台支持以真实样本验证为准。PDF.js 是备选，不首版双引擎并行建设；引擎通过端口替换，不改 OCR 文件契约。

### 网络职责与默认部署

网络管理开关按模块 / 部署配置，不写死在操作系统分支里。`managed: false` 表示沿用现有主机 / 浏览器网络，不控制出口，不是断网，也不是强制 DIRECT。

| 流量 | 当前默认与边界 |
| --- | --- |
| Codex 服务调用 | 沿用主机已配置的默认网络（使用 Clash 的主机走其默认路径）；爬虫系统不为 Codex 切节点、不参与轮动 |
| 美国 Windows 的 DTC 浏览器 | 默认关闭网络管理，继承主机环境；以后可通过部署配置启用 Adapter，不因美国位置就忽略网络失败 |
| Mac 上的渠道浏览器 | 可在固定出口下并发隔离会话；有不同出口需求时显式绑定各自监听器 / 代理，不靠全机切换 |
| 来源文件下载 | 保留所需来源会话与出口约束，必须先完成依赖该会话的下载再释放 / 轮动 |
| OCR 服务调用 | 独立配置所需路由；不随抓取出口自动切换 |
| Temporal / 入口 / 产品服务 / R2 | 使用各自稳定可达路径；R2 传输不自动沿用抓取出口 |

### 可替换的访问能力

1. 站点模块声明 HTTP、二进制下载、渲染 HTML、交互浏览器、地区及会话要求。
2. 配置 / 策略决定不管理网络，或选择已授权且能力匹配的 Provider；实际共享资源才申请许可，记录选择理由和配置版本。
3. Adapter 对接静态 IP / 代理池、Clash 或 ScraperAPI，预留其他模式。Clash 也可路由到提供的静态代理，两者不是必然互斥。

渲染 HTML 不等于交互浏览器，模拟 Page 不视为能力等价。关闭网络管理不改变抓取能力需求。失败不自动换 Provider 或重新提交业务请求；提供商自身的内部重试另行如实记录。[ScraperAPI 接口](https://docs.scraperapi.com/making-requests/api-endpoint-method)

### Clash 分组、并行与轮动

- Codex 默认组与爬虫专用组分开；不同抓取可共享固定出口并发，但会话、页签和产品状态必须隔离。
- 独立轮动的浏览器执行 Lane 需要独立可变组和明确的流量绑定，或使用独立核心。不同端口共用一个可变 selector 不算隔离；不同组名若最终指向同一个可变上游组也不算。
- 同组轮动会影响其所有消费者。首版只在本产品抓取及依赖其会话的源文件下载完成后轮动；同组有其他使用者时须全部到安全边界，不能切到一半影响规格读取。
- 只允许操作者明确授权的爬虫组及节点集合。切换后核验实际出口，不把控制 API 返回成功当作已有连接全部换路；不全局断连接 / 重载配置，不影响 Codex、OCR、R2 或其他 Lane。
- 轮动是为后续操作准备网络，不是给失败产品自动重跑。管理关闭时不发起选点操作。

Clash 节点、订阅与组配置仍由操作者管理；现有共享组选点仍遵守仓库的人工授权规则。本设计不授权修改实际节点或现有配置，未来轮动测试须限定到明确授权的专用测试资源。控制 API 仅本机 / 私网并鉴权，凭证不进任务 / 日志，保持 TLS 校验。[监听器与出口绑定](https://wiki.metacubex.one/en/config/inbound/listeners/) · [select 分组](https://wiki.metacubex.one/en/config/proxy-groups/select/)

### 网络不可用

已确认所需路由不可用时，停止领取依赖该路由的新任务，保留排队与健康告警；不让整批未执行任务变成产品失败。已经发出请求但结果未知则核验已有证据，无法确认再按实际阶段分类 Review；恢复联网不代表授权重新 OCR / Codex / 抓取 / 写入。

## 13. 界面与可观察性

- Temporal UI：执行列表、历史、Activity、等待 / 超时、消费者与版本。
- Dashboard：发现 / 处理 / 入库 / Review、渠道 / 错误类汇总、交接积压、真实采集的成本和吞吐、执行详情跳转。
- Review：被动持久记录与必要只读查询，无审批 / 自动重跑。
- 可选节点摘要：hostId、健康时间、运行模块、磁盘、浏览器 / 网络健康；不建设完整远程机器控制台。

Workflow Completed 不等于入库成功；另记 `businessOutcome`，入库以写入回执与回读为准。Search Attributes 记录品牌 / 渠道 / observationId 等必要信息，不放秘密。

Visibility 最终一致、计数可能近似并受保留期影响，不能作为长期业务账本，也不靠它轮询推进流程。准确统计来自业务库。Temporal 持久库与业务库即便共用 PostgreSQL 服务也应隔离库 / schema / 凭证，不读写 Temporal 内部表。

| A22 | 新流程历史回放 | 检查编排兼容，不重跑历史 OCR / 生产写入 |
| A23 | Formula / Ingredients 门槛 | 两者真实齐全且归属确认可入库；任一缺失精确分类；缺价格等可选字段 / 可选支线失败不新增阻塞 |
| A24 | 重复投递与新观察 | 同操作并发重复只提交一次；未知先核验；新采集不因同 URL 被跳过，显式文件复用有来源记录 |
| A25 | 资源由共享改独立 / 独立改共享 | 配置改变即可迁移；真实共享池遵守总限额，独立池不误互锁；全局写保护不关闭 |
| A26 | Windows 不管理网络 / Codex 默认路由 | 不切节点、不强制直连；网络开关不影响其他流量；不可用时未执行任务停接而非批量 Review |
| A27 | Clash 同组与独立组轮动 | 同组所有使用者到安全边界；独立 Lane 不互相改道；共享可变上游能被识别；切后核验出口 |
| A28 | DI 构建、并发与释放 | 最小 Worker 可解析依赖；任务状态不串；明确释放所属资源；业务及 Workflow 无容器依赖 |
| A29 | 正常停止与突然退出 | 先停接单再有界收尾；重启只核验证据，不重复提交未知操作；不关闭他人会话、不删证据 |
| A30 | 配置 / schema / 实现版本不兼容 | 启动或路由拒绝不兼容消费并告警；不混合在途版本，不把部署错误批量转成产品 Review |
| A31 | 渠道 / DTC 尚未完成目录 | 已可靠发现的产品立即推进；后续持续发现；不等全站大 JSON，同一浏览器导航仍串行 |
| A32 | 复用旧组件 | 有逐项审查与新契约测试；没有带入自动重试、批处理、清理和旧 Job 隐式依赖 |

## 15. 生产准入与非目标

以下是后续阶段的具体准入门，不代表本次已经测试或部署：

- P0：隔离开发验证；生产 Temporal Cloud / 自建的成本、凭证和网络选择另行批准，不在本次创建付费资源。
- P0：锁定 SDK / PDF / 浏览器版本、逐产品 partial 提交形式；未通过不得写生产。
- P0 首个验证切片：一个文件引用 → 模拟 OCR → 模拟产物 / 完成凭证 → 下游读取；无真实业务调用。先验证身份、依赖隔离、重复投递、停止和丢失回执；P1 再替换成测试 R2 / 业务登记，P2 经批准接真实 OCR。模拟通过不等于真实云存储 / 模型验证通过。
- P2：按第 7 节建立版本化证据 / family 规则和确认样例，不让模型临场决定屏障。
- P3：确认实际 Clash 核心 / API，只在授权测试资源验证选择，不修改现有共享组。
- P5：全部安全验收后批准停止旧接单、核验在途副作用、启用 V3；不把旧失败转成 V3 运行任务。

不建设通用流程编辑器、第二套调度、远程节点控制平台、全部渠道、自动下架或自动 Review 修复。生产写入、付费服务、代理配置变更和旧系统切换都不属于本次文档更新。
