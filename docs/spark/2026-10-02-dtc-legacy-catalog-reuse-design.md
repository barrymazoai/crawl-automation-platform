# DTC 目录采集复用旧机制

日期：2026-10-02。关联：CRAWLV3-170；父验收 CRAWLV3-163 / 151。

状态：用户已确认采用“复用旧机制”。本文记录设计；以下共享阶段和恢复 Shopify 对账的调整尚未实现或验收。

## 目标和边界

沿用最新旧版 DTC 的模型判断、方法 profile、目录遍历和完成证明，只将需要浏览器的操作接到 Codex 使用的 Ego 原生 skill。目录先产出真实商品 URL，单品采集保存原始资料，然后交给现有 OCR / 标签 / enrichment 流程。

保留 V3 的目录任务与单品任务分工。目录任务不调用完整商品收割，不执行 OCR 或语义处理；单品任务不重新枚举全站。单品继续保存网站真实 variants、SKU、选项、价格、状态、正文、HTML 和实际完整图库；图片未明确绑定规格时保留商品共用归属，不猜测规格。

不恢复旧浏览器进程、CDP 桥、旧控制面、自动业务重试、旧语义导出或全站任务的自动变体投送。现有模型、并发、任务时限及手动启动约束不因这次复用而变更。

## 决策

采用共享旧机制，替换当前补丁中独立维护的目录循环。保留 `discoverCatalog` 作为目录专用入口可以，但它仅组合共享枚举、证据保存和完成校验，不能再拥有另一套独立的枚举终止算法。

另一方案是维持当前独立循环、所有目录强制额外遍历。它已有测试，但重复维护旧引擎逻辑，并收紧了旧 V3 Shopify 目录的完成方式；用户已选择复用方案。

## 组件职责

### Codex 和 Ego

Codex 读取旧采集 skill 和 Ego skill，核对站点及目录范围，选择已观察到的导航、分页和加载路线。有效 profile 复用方法，失效字段按旧机制校验或重学，不把历史商品值当本次数据。

Ego 适配只承担原生页面操作、同源请求、截图和文件保存。它不判断整个目录是否完整，也不提供新的浏览器服务或连接桥。所有操作受宿主派发的精确页面及空间所有权约束。

### 共享枚举阶段

从旧 runHarvest 的 ENUMERATE 逻辑提取一个共享阶段，由旧 harvest 与目录入口共同调用。输入继续来自已校验的路线、终止契约、现有预算及枚举 hook；输出包含产品集、各 seed 的覆盖结果、轮次增长和终止原因。

保留页面 / 检查点保存回调，让 harvest 保存原有状态，目录入口保存逐页 HTML、截图及轮次记录。枚举阶段不提取商品、不解析图片、不直接发布业务结果。

复核不能因为前几页产品已经见过就提前跳过后面页面。共享逻辑应区分“本轮是否完整遍历”与“累计产品是否新增”，覆盖完整才可计算有效的零增长轮次。这是当前补丁中应保留的正确性修复，不把旧的提前结束缺陷原样搬回。

### 宿主完成校验

宿主根据明确的证明类型验收，不仅接受模型的 complete 或自填计数。两种完成证明互不冒充：

| 证明 | 适用范围 | 必须核实的证据 |
| --- | --- | --- |
| 旧枚举耗尽与零增长 | 实际观察到的普通目录路线 | 所有目标 seed 覆盖完整、翻页/加载耗尽、按原契约完成零增长复核、无可比 oracle 缺口，逐页原件与轮次集合一致 |
| 旧 Shopify 目录对账 | 符合旧 V3 有界规则的单个完整目录 | 目录实际出现的商品集合、提交集合、对应接口完整集合三者一致，并有接口末尾空页原始响应 |

普通目录首次发现 6 项、下一次完整遍历新增 0 项，在旧契约要求一个零增长轮次时即可满足轮次条件。只写 count=6 / expected=6 不能替代覆盖证明。

Shopify 证明继续复用 `shopify-all-products/1` 和 `shopify-collection-products/1` 的旧校验语义：`/collections/all` 对应全店接口；指定 collection 只与该 collection 接口对账。不能用全店接口为子目录背书，也不能把接口中未出现在目录页面的商品直接加入目录结果。

保留旧 Shopify 有界证明的限制：最多 100 个商品、按顺序读取最多两页且必须看到空终页、同站合法 handle、集合无重复及无差额；旧规则不支持的规模或路径不声称由此证明完成。它们须使用普通目录完整遍历证明。不得为了通过 HMW 而静默扩大接口页数或改变旧规则。

选择证明路径和可用性检查发生在采集计划阶段。已取得的证明出现缺项或冲突时，保留原件并返回不完整 / Review；不以切换路径掩盖冲突，不重新执行失败业务任务。

接口原始响应、DOM 证据和验证结果都进入本次采集归档。接口校验由纯函数完成，取证通过当前 Ego 原生能力；旧 CDP 取证代码不接回生产。

达到现有预算、页面不完整、接口冲突、挑战、用户接管或文件保存失败时，都保存已取得证据和具体原因，不宣称完整。原生采集的现行 no-retry 宿主约定继续覆盖旧 skill 的自动恢复部分。

## 验收依据

- 共享枚举回归：单页、多页、click / scroll、多 seed、晚出现产品、已有产品导致的假稳定、预算和覆盖失败；旧 harvest 采集输出保持兼容。
- Shopify 旧规则回归：完整集合通过；缺少空终页、接口多出/少出商品、子目录误用全店、重复项、非法 URL、响应或证据损坏均拒绝；仅平台存在的商品不入目录。
- 宿主交接回归：两种证明均需真实原件；模型声明与证据不符时拒绝；目录模式不得误入商品 harvest。
- Mini 上新的 HMW 目录验收：记录实际采用的证明、观察产品集合、每项来源、R2 全部文件大小/hash和停止/页面清理证明；DTC 批量队列保持 paused。
- 再执行独立的 HMW 多规格单品验收：网站全部规格、完整图库、原件交接与后续处理。目录通过不等于单品或全部 DTC 验收通过。

真实浏览器 / provider / 集成测试只在 Mini 运行。代码按 main 提交推送、服务器 Git clone/build 的既有部署流程到达执行机。
