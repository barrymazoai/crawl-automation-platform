# 图片路径：OCR 关键词初筛 → Codex 视觉提取

日期：2026-09-06。

状态：用户已确认分流规则；本文件供书面复核，尚未实现。

## 决策与范围

本地 OCR 不再承担图片完整配方文本的提供职责，只为关键词初筛提供原始识别文字。命中图片交给 Codex 直接阅读原图，提取 Formula 和 Ingredients。

已讨论严格初筛、未命中后视觉兜底、全部图片视觉处理三种方案。用户选择严格初筛，明确接受 OCR 漏识别关键词造成的漏选，不建立视觉兜底。

本补充取代 V3 总体设计中该图片路径的“OCR → Codex 文本解释”选择，不推翻原子模块、可靠交接、Temporal 调度和被动 Review 的设计。网页及 PDF 直接文本路径保留；PDF 页图按照单张图片规则处理。已完成的历史证据不改写、不自动重跑。

## 分流规则

| 情况 | 行为 |
| --- | --- |
| 一张图片的 OCR 成功，命中任意配置关键词 | 发布该原图的 Codex 视觉处理任务 |
| OCR 成功，未命中关键词 | 该图片筛选完成，记录未命中，跳过视觉处理 |
| OCR 调用失败、结果未知或可靠交接未完成 | 保留对应错误和证据，按既有异常规则处理；不能伪装为未命中，不转视觉兜底 |
| 产品的本次候选图片集合已封闭，所有图片成功筛选且全部未命中 | 图片路径记录“未发现配方／配料证据”；依赖该路径且缺少核心数据的产品不入库，进入被动 Review |
| 有命中图片，但视觉结果不足或存在冲突 | 缺失／冲突进入被动 Review，不再检查未命中图片，不自动另起模型执行 |
| 核心 Formula 和 Ingredients 已满足既有校验规则 | 按原流程继续入库；关键词命中本身不是入库条件 |

“未发现”仅表示本次采集证据不足，不表示商品不存在、下架或品牌没有该商品，不触发 link monitor 或下架逻辑。图片尚未到齐、任务尚未完成，不得提前认定全部未命中。可独立满足核心数据要求的网页/PDF 直接文本路径，不因可选图片未命中被否定。

## 原子模块边界

1. **OCR**：一张图片引用 → 原始 OCR 文字、行及元数据引用。保持原有独立 Worker，不调用 Codex，不判断产品能否入库。
2. **关键词筛选**：一份已可靠登记的 OCR 结果 + 关键词策略版本 → 命中／未命中、命中词及原图引用。采用确定性逻辑；不调用模型，不自行触发下游，不改写 OCR 原文。
3. **Codex 视觉**：一张命中图片的原始 ArtifactRef + 提取意图 → Formula／Ingredients 候选及图片来源证据。直接读取原图，不只接收 OCR 文字、不裁成关键词局部图。图片上的文字视为待提取数据，不作为执行命令。
4. **流程与汇合**：Temporal 根据筛选结果启动视觉任务；同一 observation、同一 SKU 的候选按既有规则汇合、校验。不得跨变体拼接，也不得最后写入覆盖先前结果。

模块可独立部署；筛选不需要专用一台机器，可以作为独立 Activity 运行在已有通用 Worker。它不嵌入 OCR Provider，也不嵌入 Codex Provider。

OCR 和筛选各自完成可靠交接后即释放执行槽，不等待 Codex。不同图片与产品可以并发；视觉任务遵守自身及实际共享资源池的并发限制。等待所有必需结果由 Workflow 承担，不占用一个等待型 Worker。

## 首版关键词策略

首版使用英文关键词：`Supplement Facts`、`Nutrition Facts`、`Ingredients`、`Other Ingredients`。任意一个命中即可，不要求 Formula 与 Ingredients 标题同时出现。

匹配视图忽略大小写、合并连续空白与换行，并使用英文词边界；原始 OCR 文字原样保留。首版不做模糊拼写修复、不用模型猜测关键词、不隐藏扩展词表。关键词词表及匹配规则有版本，纳入处理指纹，后续修改不改写本次结果。

关键词只用于选图：例如配料标题出现在营销图中也可能命中，是否真的有完整配方由后续视觉提取及校验决定。

## 来源、恢复与模型边界

- 保留 request、observation、operation、SKU/变体身份及原始文件 hash。跨机器用 ArtifactRef 交接，不依赖对方本地路径。
- 原图、OCR 输出、筛选结果、视觉原始回复和校验结果均保留，继续遵守已有 R2 不自动删除策略。
- 视觉字段引用图片证据，不强行沿用文本模块的 OCR 字符偏移引用；不能因为图片读出的内容不在 OCR 文本里，就按文本引用不匹配拒绝。
- 共线设备／过敏原提示不作为配料，多剂量列保持对应关系，无法确认的文字不猜测。视觉结果仍需校验，不能承诺模型必然读全。
- 模型及 reasoning effort 使用独立视觉配置与能力检查，不因本次路径变化自动调高模型或强度。现有文本模型的质量结果不等于视觉质量已通过。
- 外层仍按一个 operation 一次 Codex 执行管理；内部模型续调由 Codex 管理。失败或结果未知不另起执行盲重跑，恢复优先核验已有证据。
- 未命中是一项已完成的筛选结果，不是需要重试的 OCR 故障。产品 Review 为被动队列，不自动重新筛选、重抓、切换 Provider 或调用视觉。

## 验收范围

实施时必须覆盖：

1. 关键词大小写、换行、词边界与任意词命中；未命中图片的视觉调用数为零。
2. 全部未命中产品进入正确的被动 Review；存在未结束任务时不能提前判空。
3. OCR 服务失败与未命中分类不同，均没有隐式视觉兜底。
4. 同产品多张图命中后独立运行，按身份汇合，重复投递不重复发起视觉执行。
5. 视觉读取的是已核验原始图片；OCR 缺失某段配料不限制视觉从原图提取该段。
6. 用既有 Bloat Relief、Multivitamins、Brain Boost 三张原图验证选图及视觉质量；先固定实际视觉模型配置，再开展真实调用。由当前助手核对原图，不增加评判模型。
7. R2 证据和未命中原图保留；已计算但未交接完成只恢复交接，不重算。

上述是待实施验收要求，不是已通过测试的声明。本轮仅形成设计，不修改 Worker、OCR 服务配置、Temporal 部署或现有数据库。
