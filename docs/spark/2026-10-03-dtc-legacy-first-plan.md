## 2. 原本 DTC 输出后，再处理混合变体

输入是第一阶段的原始商品包和已有真实观察记录。网站给出规格 ID、选项、SKU、价格和库存；这个阶段判断已有资料适用于哪个规格，不从图片创造规格。

依材料适用范围分路，不以 URL 是否变化作为唯一判断：

| 资料状态 | 采后处理 |
| --- | --- |
| 单规格，或各规格资料已明确独立 | 保留对应关系，直接进入转换；不增加混合图库 OCR。 |
| 同一图库混有多个规格的 Facts / 资料 | 复用现有 DTC OCR 与 Codex 原图判断，将网站规格与实际图片内容对照，输出逐规格资料归属。 |
| 有充分证据明确共用 | 保存依据及适用规格；同配方不同份数、包装或警示仍分别处理差异。 |
| 证据不足、互相冲突或缺少状态 | 保留原件和具体缺口；只隔离受影响规格。需要补证时沿用旧流程的定向处理出口，不猜默认规格、不重抓整站。 |

不按图片文件名、alt、顺序、关键词或“图库没变”决定归属；不能因为 URL 带 variant 就声称资料隔离，也不能因为 URL 不变就判无解。不同营养数值、份数、口味配方和 Other Ingredients 差异均保留。

优先复用已实现的 `DtcMixedGallery`、OCR/原图模型判断与 Solaray 2/2 的验收证据，调整输入边界；不再重写一套混合图库算法，不改变其他渠道共享 Facts 主流程。采后结果作为独立派生产物引用原件，不能覆盖旧输出。已有模型/OCR回执是否能安全复用按来源和现有协议核实，不虚称跨任务缓存已实现。

验收第二阶段：独立材料不误入混合分支；混合材料正确对应每个规格；不同配方/份数不被复制共用；一个规格不确定不丢其他已确认规格。复用 Solaray、HMW 留存材料先做离线验证，再补真实独立材料样本。

## 3. 固定转换器：把旧输出与归属结果交给下一步骤

输入固定为“第一阶段原始商品包 + 第二阶段归属/待审结果”。转换由可测试的代码完成，模型无需逐商品编写转换脚本。以确认后的旧输出为依据定义映射，不反向要求采集改造成新版协议。

| 输入内容 | 转换要求 |
| --- | --- |
| 商品 URL、标题、品牌及来源 | 保留真实身份与出处，不补任务期望品牌；基础商品不自动变成默认规格。 |
| 完整网站 variants | 逐项保留 ID、SKU、选项、价格、货币、库存，包括缺货项；不以任意首项回填。 |
| HTML、网页正文、原图 | 保留原文/必要 HTML 结构、文件引用、大小/hash及状态来源；不重新访问网站、不丢弃原始完整图库。 |
| 第二阶段逐规格归属 | 生成各规格适用的材料引用及明确待审状态，进入现有 source plan / Facts / 逐规格处理。 |
| coverage、flags、缺项与冲突 | 如实传递，区分真实缺失、未检查、适用范围不明和转换失败；不将空值伪装成成功。 |

优先审查并复用现有 `product-projection.ts`、`variant-handoffs.ts` 及旧 `dtc-legacy-evidence.ts` 中纯转换部分。去除对新采集专属证明的错误依赖，不复用其中自动猜字段或无证据复制共享配方的行为。旧 `toEnrichProductInputs` 的共享基础结果展开方式只作为风险对照，不能直接拿它跳过混合判断。

阶段二可有内部数据封装，但正式下游计划在归属决定后生成；不能先按默认规格投送，再修改旧结果。转换不负责 OCR、语义猜测或重新抓取。转换失败优先用留存原件修复/验证，历史业务失败仍保留，禁止自动业务重试。

验收第三阶段：输入/输出商品与规格数量可对账；字段、金额/货币、库存、资料归属及原件引用正确；同一输入可稳定重放；部分规格 Review 被隔离；不会重复生成业务投送。原始未带新版证明的旧样例也能按其真实证据链读取。
