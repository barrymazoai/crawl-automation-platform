# DTC 原生采集补充设计：职责、状态与证据交接

日期：2026-10-02。主票 CRAWLV3-172；关联 148、150、151、155、163、164、165、166、167、169、170、171。

状态：按用户要求进行修改前复核，本文是拟采用的实现与验收边界，不是功能已实现声明。本轮只读代码/历史记录并更新文档与 ticket，没有修改业务代码、部署或发起新测试。DTC 批量仍保持暂停；此前 HMW 6 个目录项没有批量投送。

## 用户约束与旧版基准

用户明确：恢复最新旧 DTC 采集步骤，只把 Chrome 换成 Codex 操作 Ego；先采原件，再交原有后处理；规格来自网站；保留完整实际轮播图；禁止通用提取器；每次修复与验收记 ticket。

已核对旧部署 b891f0d 对应相关实现 20b09db、旧 skill、旧 V3 capture、Shopify hooks，及当天真实失败证据。旧完整 skill 的自动恢复、语义队列和最终逐规格导出不能直接搬到 V3 capture-only 任务。原版存在的默认 SKU/价格回填或宽泛提取行为，也不能因为“复用旧版”继续保留于已被用户收紧的原生采集路径。

## 一、入口应只有一套明确的阶段职责

| 阶段 | 模型要判断什么 | 程序执行与验收什么 | 交给下一阶段什么 |
| --- | --- | --- | --- |
| 站点分析 | 官方身份、直属品牌、目录入口、平台和范围 | 保存观察证据，检查来源边界 | 来源候选与分析结论；不自动表示已应用或已抓全目录 |
| 目录发现 | 实际商品入口、目录族、分页/加载路线、完成证明选择 | 执行确认路线、记录每页、按旧枚举或有界 Shopify 证明核验 | 去重后的基础商品及明确规格入口，目录证据；入队不等于启动 |
| 单品采集 | 当前商品身份、字段来源、规格状态、真实完整图库 | 执行已验证方法、保存原始 HTML/JSON/图与逐字段证据 | 完整原件、网站字段、规格、关联关系及缺失/冲突说明 |
| 后续处理 | 原有 OCR/标签/语义判断 | 从本次存档读取，保持商品与规格身份、追踪处理结果 | 标签、标准化信息及逐规格处理结果或明确 Review |

目录不得调用单品收割；单品不得重新从详情页“发现自己”或收推荐商品；capture 不执行旧 semantic queue/enrich/export。不能让冲突的旧整站说明与新的单品说明共同决定行为。保留旧通用工具用于其他合法路径，不意味着原生 DTC 可自动调用它们。

## 二、禁止通用提取要覆盖所有调用层

172 已复现的错误：HMW 的描述为购物车文本、基础价格为推荐商品价格。模型虽然选择了字段节点，旧 profile 引擎未执行该 CSS 后静默退回全页匹配；仅检查非空的采前验证误判通过。

拟修改边界：

- 原生 DTC 不调用通用 HTML 字段提取、关键词扫描、猜测字段、自动 extract/upgrade fallback；模型自定义 hook 内也不能再包同一通用提取器。
- 必须显式提供本次已验证的站点读取方法；缺方法/失效时返回模型局部重新观察，不能自动切入 `extractProductsBatch` / `upgradeProducts` / `applyDetailExtractionProfile`。
- 允许普通 DOM/API 操作执行模型已确认的 selector、JSON 字段路径，以及成熟平台的明确协议映射；这与按整页内容猜字段不同。共同代码负责 IO、身份/集合/hash 校验，不重新选择语义数据来源。
- 审计 capture prompt、默认 hooks、升级路径、`buildEvidencePackage` 回填、projection 和后处理输入。禁止只改提示词或只屏蔽一个入口。
- 不能仅凭函数名称/静态扫描声称模型不可能绕用通用提取；需要清晰受支持入口、运行证据与负向测试。宿主不得为验证再引入第二个通用爬虫。

## 三、平台数据是明确来源，不是无条件最高优先级

恢复旧 Shopify 商品数据提取方法时，只处理目录已发现或宿主明确派发的商品，不把平台库存扩成可见目录。先确认真实平台和商品身份，不能仅见 `/products/` 就认为返回内容属于目标商品。

平台/嵌入式 JSON 要保存原始响应、实际最终 URL、商品 ID/handle、规格 ID、时间、大小与 hash；异商品、挑战 HTML、未验证重定向、不完整响应不能被解释成“无规格”。接口缺字段时，模型可在正式收割前按已观察页面补充，而非静默启用通用提取。模型若读取非标准内嵌对象，也须指明实际对象与当前商品的对应证据。

网页可见值与平台数据冲突时保留两份来源，由模型核对是否由所选规格、地区、货币、促销/订阅方案或陈旧数据导致；无法解释则保留冲突。不得用任选一个值掩盖差异。品牌期望值只能用于校验，不能代替实际品牌。

## 四、读取原件不能改变已验证的页面状态

**代码审计发现、尚未专门复现：** 新 `ego-native-browser.mjs` 的 `fetchPageHtml(url)` 在当前 URL 不完全相等时执行 `goto(url)`。旧 Shopify hook 使用同源 HTML fetch，不以此导航。当前已选择 variant 的 URL 与基础 URL 不同，保存 HTML 时可能重置选中规格、已展开区块和懒加载进度。

需区分三个操作及其证据类型：显式导航、读取当前渲染 DOM、获取原始 HTTP 文档。读取当前页面不得暗中导航。切规格后由模型观察更新完成，记录 URL、商品/variant ID、选项、价格/库存、图库与截图；DOM/JSON/截图/图片应引用同一观察状态。不同时间或状态的版本可以保留，不能拼成一份伪装同时发生的快照。

当前渲染 HTML 是 DOM 序列化，不是 HTTP 响应字节，存档类型必须如实区分。价格货币、地区和订阅/一次购买也属于观察状态；缺乏可靠证据时不擅自更改这些用户状态。

## 五、验证字段来源和内容，不能只验证非空

每个采集字段需要能回指到本轮原件及具体状态：来源类型、selector/JSON 字段路径、商品/规格身份、原始值和模型核对结论。保留未改写的原文；清洗/标准化是明确的后续步骤。

模型采前逐项核对实际返回值与页面/平台内容，采后核对正式保存值。宿主可检查引用存在、原件 hash、明确路径的值与保存值一致，不能替模型虚构“已视觉确认”。方法与正式执行之间发生变化则重新验证该方法；同一个有 bug 的函数前后输出一致，不足以证明字段正确。

区分：已取得；检查后确实不存在；尚未完成检查；多个来源冲突。图片形式的 Facts 没有正文，不等于缺失标签。可选描述缺失、无法取得必需原图、商品身份不明的处理后果各不相同，不能一律强塞非空值或判整商品失败。

## 六、完整规格与基础商品身份要贯穿交接

- 保存网站真实列出的规格，包括售罄项；非平台站仅记录网站真实存在的选项组合，不自行构造笛卡尔积，也不把订阅频率、加购数量当规格。
- 基础商品 URL 仍为基础商品；不能因网页默认选中规格而改成该规格任务。显式 variant URL 则严格检查目标规格。
- 移除原生路径的任意默认 SKU/价格回填。逐规格值跟随对应规格；基础字段只有明确商品级或明确选定规格依据才填。HMW 9.99 与34.99不能任选为基础商品价格。
- 图片关系至少区分网站明确绑定、经证据确认共用、尚未明确归属。共用/未知都可以保留原件，但不能因此把公共 Facts 自动复制给不同配方。
- **代码审计发现：** 当前 projection 对基础多规格商品将全部图统一映射为 variantId=null，原始绑定仍在 archive。后续是否利用这些绑定必须单独核验；不能拿“原件保存了”替代“后处理收到且使用了”。
- 旧完整 skill 最后会逐规格导出；现行 V3 的保存 variants 不等于已经逐规格投送。需要写清展开由哪个已有阶段负责，并验最终数量、身份、包装/选项和配方对应。不得重新启用旧导出器或假称所有规格已成功。

## 七、完整图库与原图取得分开验收

模型需覆盖轮播后续项、横向滚动、懒加载、展开详情与规格切换后出现的图片。商品主图、详情图片与推荐/徽章由真实页面观察区分，不以文件名/alt关键词决定收集集合。

只能采用实际观察到或可靠验证的原图地址；清晰度与内容均核验，不能删尺寸参数来猜原图。同一文件不同宽度可按已验证资源身份去重，但裁剪、语言、包装版本、不同文件不能仅因 URL 相似合并。下载前后的商品/规格关系不能因去重丢失。图集完整与某张图包含 Facts 是不同判断，后者交既有处理阶段。

已保存文件数量、尺寸和模型自填 `galleryComplete=true` 都不足以证明轮播看全；保留逐项观察与最后状态。Codex JSONL 未提供独立看图事件也不等于没看，不能凭日志缺项制造失败结论。

## 八、profile 必须适配新的任务粒度和浏览器能力

原 profile 只存方法，不存商品值。需要绑定站点/模板、方法版本、浏览器能力版本和有效验证记录；Chrome/CDP 专有动作不能因同名接口存在就被认为已适配 Ego。

旧规则要求代表样本真实通过后晋级，通常至少两个详情，只有确认全站单商品时例外。**单品任务并不意味着整站只有一个商品**：本任务可以用临时方法完成采集，但不能据一条成功样本把方法标为全站已验证。多个受控样本积累后再晋级正式 profile。

失败样本不覆盖已验证版本，不将 successCount 或 passed 布尔值当实际证据；候选与正式版本分开。多任务或多机复用同一方法时，需核对版本来源及写入冲突，而非假定本地目录会自动同步。该部分为待核验设计，未宣称当前跨机 profile 同步已实现。

## 九、采前纠正、原件重放与业务重试是不同动作

模型允许在正式收割前基于已取得原件修正路径/字段方法并重新验证；必要页面交互仍有明确范围和预算。原件已采集后发现提取错误，诊断优先使用存档，派生修正写新版本并引用旧原件，禁止删除 capture/checkpoint 后 fresh 重跑。

保留所有失败原件和原 Review。旧 skill 中自动 retry、replace tab、resume 等能力不能越过 V3 的禁止自动业务重试与页面所有权要求。只读状态核验、已知未发生的操作纠正、失败业务重新执行应分别记录。允许的后续受控验收使用新 ID，不伪装成旧任务成功；归档失败不能反向触发再抓网页。

## 十、Ego 迁移需要实际能力门和明确资源收尾

已遇到：code-mode host未启用、显式undefined被Ego拒绝、每次nodejs进程不共享句柄、恢复Page没有targetId、窗口隐藏导致截图超时。操作必须按Ego原生skill，记录CLI/模型/skill/profile/代码版本；用实际能力检查判断，不能靠旧Chrome API名称推断支持，也不能把所有截图超时判为锁屏或站点不可用。

每次操作核对TaskSpace所有权和精确target。用户接管即停止；不自动takeover、不关闭无关页面、不重启整个浏览器。HTML/JSON/图片一取得即留独立原件；完成需要 live page 的有界阶段后关页，不为OCR/R2上传继续占页。

正常、Review、取消、超时均需实际进程结束、精确任务页不存在、账本停止证据和许可释放。R2归档失败、数据库中断、模型503、浏览器执行失败、字段不完整应分开报告。Worker SIGKILL孤儿Codex自动恢复仍是150的未完成项；单次正常关闭不能替它验收。异常演练先隔离任务，不能直接强杀生产共享浏览器。

## 十一、下游字段与成功口径单独验收

网站包装数100ct曾在采集成功后丢在enrichment交接；此前Workflow COMPLETED也曾包着业务Review。需分别记录：目录发现数、原件齐备数、已交接数、业务collected数、逐规格处理数、Review/失败数和清理状态。

投影是协议转换，不应在此重新抓网站、填期望品牌、丢弃原始SKU/选项/库存/关联或凭默认值改身份。宿主核验归档与字段引用之后，后处理只读已保留版本，核对最终使用的HTML/图片hash与采集一致。单品pass不等于整品牌pass；历史固定DOM结果不等于新原生结果。
