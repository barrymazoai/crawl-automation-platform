# Clash 固定出口兼容设计：真实地址解析＋专用监听器

2026-09-07。用户已选择第一条路线。本文细化原 Temporal V3 设计第 12 节，不替换其职责边界；当前为设计交付，代码与实际 Clash 配置尚未按本文修改。

## 1. 决策与范围

采用可注入的真实地址解析器与明确绑定分组的专用监听器，继续使用公网 IP 固定连接及目标 TLS 校验。不采用共享代理端口按域名重新解析目标的路线，也不通过放行 Fake-IP 修补 GNC。

本次设计覆盖原始 HTTP 页面与二进制来源文件的固定出口兼容、能力预检和安全拒绝。浏览器拥有者运行时、自动轮动、ScraperAPI、Web 配置下发不在这一个实现切片内，接口边界为后续保留。固定出口兼容不能冒充完整网络管理或浏览器采集实现。

验证机器固定为 Mac mini `barry@192.168.0.25`；当前电脑可检查、编写和构建，不执行业务或网络验收测试。PDF 继续暂停。

## 2. 已知证据与原因

Mini 系统解析 `www.gnc.com` 返回 `198.18.0.9`，现有 `pinAddress` 正确拒绝保留地址。现有 `StaticProxyTransport` 将已校验的公网 IP 放入 CONNECT，保留域名用于 Host/SNI。Mini 现有规则按 `gnc.com` 匹配 `GNC出口`，因此单独修复 DNS 不足以证明 IP CONNECT 仍使用指定出口。

实机探针为一次 DNS、零 transport 调用，错误 `SOURCE.SSRF_BLOCKED`；不能据此推断站点不可用、商品缺成分或图片不存在。[实机报告](../quality/2026-09-07-gnc-mac-mini-network.md)

Mihomo 文档支持监听器通过 `proxy` 明确绑定代理或分组，不指定时才使用规则。我们选择显式绑定，不依赖 IP 请求的域名嗅探。[监听器文档](https://wiki.metacubex.one/en/config/inbound/listeners/)

## 3. 模块职责

| 单元 | 职责与依赖 | 不负责 |
| --- | --- | --- |
| 共享网络契约 | 模式、路由 ID、版本、配置指纹、所需能力 | URL 密钥、控制器凭据、业务流程 |
| Clash DNS Adapter | 经受信控制端解析、验证答复结构、提供真实 A/AAAA 地址 | 修改系统 DNS、放行 Fake-IP、自动换 DNS 服务 |
| Clash 固定路由 Adapter | 核验监听器绑定、固定出口配置，组合 DNS 与现有 CONNECT transport | 修改订阅、创建节点、全局切组 |
| 网络工厂 | 从已校验私有配置组装一致的 resolver/transport/健康状态 | 发起产品抓取、选择备用 Provider |
| 来源访问与租约接口 | 核验产品授权、会话、路由版本及使用期限 | OCR、模型执行、产品入库 |
| Worker 运行层 | 启动与接单能力门禁，健康状态变化时暂停相关接单 | 把网络故障批量变成产品失败 |

实现继续位于 `packages/v3-acquisition`，公开元数据属于 `packages/v3-contracts`。GNC 等站点模块只消费网络端口，不导入 Clash 控制器。文件与页面使用同一个工厂得到的网络上下文，不能一个注入真实解析器、另一个仍用系统 Fake-IP 解析。

共享契约新增显式 `clash` 模式，使用独立兼容版本的消费者，不暗中改变旧 `static-proxy` 的含义。工厂组合输出必须包括 DNS、transport 与路由健康检查；现有 direct/static-proxy 使用原有语义。不管理网络仍要求真实拥有者客户端，不等于强制直连。

## 4. DNS 与目标连接

首版解析接口选用受信本机 Mihomo 控制器的 `GET /dns/query`，分别查询 A/AAAA。接口提供的是 DNS 查询能力，**文档并不替代安装版本的行为验收**：只有 Mini 实测能提供通过校验的真实地址时，此解析器才能进入可用状态。[控制 API 文档](https://wiki.metacubex.one/api/)

规则如下：

- 控制器地址来自私有部署配置；仅允许明确配置的本机接口，鉴权数据不进入 Temporal 或普通日志。禁止通过任务提供任意控制器 URL。
- 单次查询上限 5 秒、64 KiB、64 条记录，A/AAAA 总解析期限 10 秒；CNAME 最多 8 层且不可循环。校验响应状态、问题域名/类型、记录类型、地址语法与域名关联，不能收集无关 Additional 中的地址。
- 一种地址族合法 NODATA 可接受，但两族合并后必须至少有一个有效公网地址；截断、异常响应、无法确认的 CNAME 关系均失败关闭。不悄悄回退系统 DNS、公共 DoH 或直连。
- A/AAAA 结果中的目标地址必须全部满足现有公网策略；Fake-IP、私网、回环、链路本地、映射/隧道地址等不能放行。未知不视为安全。
- 使用选定真实地址做 CONNECT，禁止代理重新按目标域名解析；HTTP Host、TLS SNI 和证书校验仍使用原域名。
- 每次新请求/重定向重新执行相应校验；DNS 查询不重试。文件原有 HTTPS/origin、重定向、字节/像素限额及取消规则保留。
- 如果 Mini 当前 `/dns/query` 也只能给出 Fake-IP，本实现报解析能力不可用，保留证据；增加其他 resolver 需要显式配置与单独验证，不临时放宽地址规则。

代理和解析器仍是受信基础设施。公网 IP 固定及 TLS 能防止应用层地址漂移、保护目标身份，但不宣称能证明一个恶意上游代理实际访问了哪个地址。

## 5. 专用监听器与固定出口

数据流：产品授权 → 路由预检 → 真实 DNS → 公网地址校验 → 专用监听器 CONNECT → 指定固定分组 → 目标 TLS。

- 专用 HTTP/mixed 监听器只绑定 Mini 回环地址，不向公网或整个局域网开放。
- 显式绑定爬虫测试专用组；固定阶段该组只使用已授权固定节点，不依赖仍可由旧 Worker 改动的共享可变 selector。不同端口绑定同一个可变组不算隔离。
- 首次部署核实端口占用、Mihomo 版本和实际生效配置，并记录 listener → group → leaf 的完整关系；校验未知就不启动消费者。
- 整条上游链不能含未授权自动选择、fallback/load-balance 或共享可变依赖；不能仅凭外层组名宣称固定出口。
- 通过同一监听器的受控出口探测及连接链证据确认实际流量绑定。控制 API 返回选点成功、节点名含“美国”或 IP 地理标签均不单独作为验收。
- 运行期间发现配置版本/上游关系变化即暂停新操作；已有进行中操作标记受影响，核验其证据，不冒充仍保持同一会话。读前/读后核验不宣称具有原子防切换能力，隔离部署和所有权是固定阶段的必要前提。

用户选择本路线不等于已授权修改 Mini 当前共享核心。实际部署前需列出准确新增监听器、测试组、节点引用、配置生效方式与恢复方式，请用户确认。若现有核心无法无干扰生效，则停止该配置变更并提出隔离核心方案，不重载共享核心作为隐式兜底。

## 6. 并发、租约与错误处理

固定出口可供多个独立产品并发使用，各请求独立连接、Cookie、授权和取消。释放一个下载请求不能关闭其他请求连接。

处理完成可以释放 Worker 执行槽；来源会话仍被下游需要时，不同时释放逻辑网络租约。固定阶段不自动换节点，租约绑定 route/version/session 并持续核验；恢复运行不能仅凭内存中曾存在租约就认定其仍有效。

将来启用轮动前，必须有跨相关 Worker 的可靠租约协调：所有依赖该出口的页面/文件使用者到达安全边界，未知完成或过期租约不能直接当成允许切换。协调属于共享资源层，不占用一个 Activity 等待下游，也不把 lease 状态藏在单个 Worker 内存中。本切片不实现轮动，不能提前对外声称这些跨 Worker 轮动条件已验收。

错误分两类：

1. 启动/接单前已确认网络能力不可用：停止领取依赖该路由的新任务，任务留队，显示健康异常；不批量写产品 Review。
2. 已领取或已经发出请求的操作发生异常：区分未执行、已执行、未知；保留阶段证据。未知只读核验，不自动重抓、换出口或调用备用服务。已收到的内容仍遵守原不可变保存及 Review 规则。

若共享 Worker SDK 不能仅暂停一个 Activity 能力，使用该独立角色的受控停接/优雅退出；不停止其他角色，不以取消全部进行中操作代替正常停接。

## 7. 保持不变

- Temporal 编排与原子 Worker 边界不变；不增加中心网络调度平台。
- Codex 默认路由不变；不参与爬虫轮动。
- Windows DTC 默认不管理网络，仍使用自己的浏览器运行时。
- OCR、R2、Temporal 与业务 API 各自连接配置不自动继承爬虫出口。
- 页面与相关图片保留所需的产品/规格/会话/出口关系，私有凭据不进入任务历史。
- 产品入库仍依赖可靠 Formula 和 Ingredients 证据，不因为网络兼容增加业务字段门槛。

## 8. 验收标准（均在 Mac mini）

| 场景 | 必须观察到的结果 |
| --- | --- |
| 系统 DNS 继续返回 Fake-IP | 不修改系统设置；新解析器取得已校验真实地址，或明确拒绝而不发源站请求 |
| 解析含私网、保留地址、无关记录、错误响应 | 不进入 CONNECT，不隐式回退 |
| IP CONNECT | 确认专用监听器/指定固定链，Host/SNI/证书校验正确 |
| 监听器、组、叶节点或配置不匹配 | 停接新任务，旧组/默认流量不被修改 |
| 两张图片并发，取消其中一张 | 授权和连接互不串用，另一张正常继续 |
| 图片重定向到其他 origin | 显式授权才允许，Cookie/Authorization 不跨源传播 |
| 依赖网络不可用时提交多个任务 | 未执行任务仍排队，非批量产品 Review |
| 请求完成后回执未知、空缓存替代 Worker | 核验既有证据，不新抓取、不重新上传已完成产物 |
| 实际 GNC 单 SKU | 记录请求上限、真实 HTML/SKU及页面元素/图库检查；下载成功不等于产品完整 |

顺序门槛为能力/安全验证 → 专用出口核验 → 单品页面/图片 → 既有处理链路。各阶段真实模型/R2调用仍按既有授权和限定样本执行，不将本设计视为批量或付费调用新授权。任何阶段未通过，报告具体缺口，不把整项 CRAWLV3-33 标记完成。
