# Amazon 原图保存与上传分段验收

上一轮同组十商品耗时 957.880 秒，浏览器资源占用 855.202 秒。此次将原图本地保存与云端上传分开，让上传和解析能与下一个商品抓取重叠。目标仍是争取十分钟，实际耗时须以新一轮验收为准。

## 流程与边界

- 保持正式 Brand 入口和 Temporal 调度。浏览器容量一、纽约 10001、购买条件解析、模型和标签选择规则保持原配置。旧百商品批次继续暂停在 24。
- 抓取页面并生成原有产品计划后，capture Activity 串行下载该商品全部原图。每份原图经格式、大小、哈希和归属校验，保存到现有 Mini 私有内容寻址缓存，落盘并重新读回核验。另保存每份原图的输入及归属记录。
- 全部原图保存完成后发布一个共享分段清单。该清单状态为 `staged`，只表示本地保存完成，不是云端持久化回执，不能直接启动图片识别或提交商品。
- 关闭本任务的精确页面，确认目标已消失，再释放浏览器许可。之后启动标签流程，并由 file Worker 以最多两个 Activity 并行上传原图。
- 发布端核对相同物理存储身份、原始清单、页面关闭账本及本 Workflow 的许可释放记录，随后只读取本地原图。没有下载能力的冷实例也能完成正常上传。
- 每张图片按原有不可变对象流程上传、回读校验、发布采集完成回执；只有完整回执才能通知标签流程。全部原图完成后才发成功收尾信号。其他商品可在此期间使用已释放的浏览器。
- 共享执行标记阻止重复访问原站；上传使用独立原图标记。丢失回执只做读取核对，不重新 PUT。不能确认的结果保留为待处理，原图和历史证据不删除。
- 已完成的本地分段可供冷实例读取。尚未完成的分段或不确定上传仍需证据恢复，不宣称能自动无条件续传；本地文件丢失或损坏也不隐式重新抓取。
- 原下载 Activity 保留用于旧任务历史；新路径由 Temporal patch `amazon-detached-file-publication-v1` 控制。
