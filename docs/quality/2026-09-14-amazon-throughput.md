# Amazon 十商品连续流水线验收

目标：同组十商品在正常 Temporal 流程下争取十分钟、验证能否进入十至十五分钟。上一轮处理耗时 1933.885 秒（约 32 分 14 秒），另有 189.180 秒人工验收暂停。不能将预计时间当成实测结果。

## 瓶颈和改动

上一轮浏览器资源占用合计 954.629 秒，已经超过十五分钟；并非只提高 AI 并发就能解决。任务主要重复读取同一份保留证据，且每组两个商品全部结束才开始下一组。

- 在 Amazon、产品计划和标签 Activity 内复用成功的不可变对象 GET，限单次调用，最多 32 MiB / 512 项。不同 Activity、重试及并发调用不共用结果；缺失、失败、发布占用标记不复用。
- 保持哈希、对象身份和大小检查。create 前后使该键失效，PUT 返回值不能作为持久化证明，仍需回读。复用字节返回独立副本，取消和内存上限继续生效。
- 同一计划的两份保留证据独立校验；标签收尾每组并行检查最多四张原图。任何一张缺失仍阻止提交；等待已启动检查结束后才返回错误。完整标签已找到也不丢弃其它原图。
- 显式 Amazon 链接请求上限由四条改为十条，使用正常 Brand API 一次提交同组十条，消除成对批次之间的等待。浏览器许可仍为一、模型与 OCR 许可保持原配置，资源等待上限不变。
- 不改 Workflow 可执行代码或旧历史，不更改模型、指纹、购买条件、区域、邮编、权限和私有凭据。
- 每次 Activity 输出不含对象键或内容的读取次数与复用次数，便于现场核对节省的请求。
